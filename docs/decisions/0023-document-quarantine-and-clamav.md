# ADR 0023: Quarantine before protected document release

**Status:** Accepted for local and hosted launch hardening

## Context

Booking documents may contain contracts, passports, KYC statements, CDD evidence
and invoices. Filename extensions, browser MIME declarations and a human review
checkbox do not establish that a file is safe to open or mirror externally.

## Decision

- Browser uploads enter the private `booking-quarantine` bucket first.
- The application validates size, declared type, file signature and disallowed
  PDF encryption/active-content markers before upload.
- Each record has a SHA-256 checksum and an explicit scanner state.
- A local ClamAV daemon is the initial scanner adapter. Scanner outages preserve
  quarantine state; they do not fail open.
- Only a clean file copied into `booking-private` receives the `released` state.
  Signed URLs, human verification, contract review and Drive synchronisation all
  require that state.
- Infected files are removed from Storage after a scan/audit record is retained.
- Deterministic invoice PDFs are generated by a trusted server-side service and
  are separately marked as generated/released with a checksum.
- Retention remains alert-only until Torrance approves a documented KYC/passport
  retention schedule.

## Consequences

The local automation Compose stack now includes ClamAV on loopback port 3310.
The hosted stack keeps it on the internal Docker network. A real document cannot
be accepted while the scanner is unavailable, so production activation requires
scanner health monitoring and a tested retry/recovery procedure.
