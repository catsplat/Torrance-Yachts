# Incident response runbook

## Priorities

1. protect people and sensitive information;
2. stop further unauthorised access or external actions;
3. preserve evidence and authoritative records;
4. restore safe internal operations;
5. communicate through the client-approved route;
6. learn and prevent recurrence.

## Immediate containment

- suspend the affected application worker route and integration connections;
- rotate compromised provider/shared secrets;
- deactivate affected user accounts without deleting audit history;
- revoke public sales-material links if relevant;
- do not delete suspected records, logs, messages, or documents;
- use manual email/phone procedures while the core database is unavailable.

## Assessment

Record detection time, reporter, affected environment, accounts, providers,
records, identity documents, external recipients, suspected cause, containment,
and decisions. The client/data-controller decides regulatory, contractual, bank,
insurer, and affected-person notification with appropriate professional advice.

## Recovery

Restore through the tested runbook, verify security controls before reconnecting
providers, and monitor closely. Record a post-incident review and update tests,
runbooks, permissions, or training.
